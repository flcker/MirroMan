# 模型与执行策略

## 设计原则

策略层与工具层解耦：上层定义**场景→模型级别**的映射，下层各工具自行配置模型级别对应的具体模型名。

## 模型级别定义

| 级别 | 代号 | 适用场景 |
|------|------|----------|
| 轻量 | `lite` | 简单问答、单文件小改动、搜索、确定性任务 |
| 标准 | `std` | 日常开发、代码生成、常规重构 |
| 专业 | `pro` | 多步推理、架构决策、复杂调试、安全审查 |

## 场景→级别映射

| 场景 | 模型级别 | 执行模式 |
|------|----------|----------|
| 主会话协调 | `pro` | 主会话 |
| 单文件小改动 | `lite` | 主会话 |
| 多文件重构 | `std` | subagent × N |
| 批量搜索/检查 | `lite` | subagent × N |
| 代码审查 | `std` | subagent × 模块 |
| 测试分析 | `std` | subagent |
| 架构决策 | `pro` | 主会话 |
| 探索性调研 | `lite` | subagent |

## 切换规则

- **新增工具**：在「工具适配配置」下新增一个小节，填写三级模型映射。
- **调整级别**：只需修改「场景→级别映射」表中的模型级别，无需逐个工具改模型名。
- **切换工具**：修改当前激活的工具标识（如 `active_tool: deepseek`），AI 按对应工具的配置表解析模型名。
- **混合使用**：不同 subagent 可指定不同工具，主会话在分发时注明即可。

# 文档规范

所有项目文档统一存放于 `docs/` 目录，按版本分层、按类型分子目录。

## 目录结构

```
docs/{version}/
├── design/          # 技术设计
├── guides/          # 使用指南 / 运维手册
├── conventions/     # 团队约定 / 编码规范
├── adr/             # 架构决策记录（plan 伴生）
├── changes/         # 变更说明（plan 伴生）
├── api/             # API 文档（plan 伴生）
└── summary/         # 实现总结（plan 伴生）
```

- 有明确版本号时放在 `docs/{version}/` 下，与 plans 目录版本号对应。
- 无版本号时放入 `docs/default/`。

## 文档分类

| 分类 | 子目录 | 说明 | 触发时机 |
|------|--------|------|----------|
| 技术设计 | `design/` | 架构、模块、选型方案 | 设计方案确定时 |
| 使用指南 | `guides/` | 部署、配置、排障 | 功能交付时 |
| 团队约定 | `conventions/` | 评审、工作流、命名规范 | 团队共识后 |
| 架构决策 | `adr/` | 关键选型与权衡 | plan 涉及架构决策时 |
| 变更说明 | `changes/` | 执行过程与改动记录 | plan 创建/完成时 |
| API 文档 | `api/` | 新增或变更的接口 | plan 涉及接口变更时 |
| 实现总结 | `summary/` | plan 完成后回顾 | plan 完成时 |

> 通用文档（design/guides/conventions）独立于 plan，按需创建；其余为 plan 伴生文档。

## 命名规则

文档命名简洁描述主题，格式 `{描述}.md`：

- `认证系统设计.md`、`部署指南.md`、`代码评审规范.md`
- ADR 加序号前缀：`001_缓存策略选型.md`

Plan 伴生文档与对应 plan 主标题一致：

```
plans/v1.0.0/feat_新增用户认证_2026_05_16.md
    ↕
docs/v1.0.0/changes/新增用户认证.md
```

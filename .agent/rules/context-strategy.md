# 上下文管理策略

## 核心原则

避免主会话上下文溢出，通过 **分流-压缩-回收** 三阶段保持上下文在安全水位。

## 上下文水位

| 使用率 | 状态 | 动作 |
|--------|------|------|
| < 40% | 安全 | 正常执行 |
| 40%–60% | 预警 | 审视是否需要分流，避免一次性大文件读取 |
| 60%–80% | 警戒 | 主动分流子任务至 subagent，触发 `/compact` |
| > 80% | 危险 | 立即压缩，暂停新的大上下文操作 |

## 分流策略

### subagent 优先
- **多任务并行**：将独立子任务分发到 subagent，主会话仅负责协调与汇总。
- **大文件分析**：超过 500 行的文件分析交给 subagent，主会话只接收摘要。
- **批量搜索/检查**：跨文件的模式搜索、代码审查交给 subagent。
- **探索性调研**：未知代码库的走读调研通过 explorer subagent 进行。

### 分流决策矩阵

| 场景 | 主会话 | subagent |
|------|--------|----------|
| 单文件小改动 | ✅ 直接执行 | — |
| 多文件重构 | 🔀 协调 | ✅ 分文件执行 |
| 批量搜索 | — | ✅ 每个搜索方向一个 |
| 代码审查 | — | ✅ 分模块审查 |
| 测试运行 | 🔀 触发与汇总 | ✅ 分析失败原因 |
| 架构决策 | ✅ 集中决策 | — |

## 压缩策略

- **自动触发**：上下文水位超过 60% 时，主动建议 `/compact`。
- **手动触发**：长会话中每完成一个独立阶段后，评估是否需要压缩。
- **压缩后恢复**：压缩后立即读取 AGENTS.md 和关键规则文件，恢复项目上下文。

## 上下文回收

- 子任务完成后，仅保留其 **结论、文件变更清单、待跟进事项**，丢弃中间推理过程。
- subagent 返回结果后，主会话只存储摘要（不超过 10 行），不复制完整输出。
- 不再需要的历史中间产物（如已被后续修改覆盖的补丁），主动从上下文移除。

## 文件读取节制

- 避免一次性读取大文件全文，优先使用分段读取（`start_line` + `max_lines`）。
- 先用 `grep_files` 定位关键区域，再按需读取。
- PDF/文档类大文件使用 RLM 会话加载，不直接塞入主会话上下文。
